使用方法

  1. 在仓库的 Settings -> Pages 中，将分支来源设置为 gh-pages 或工作流自动发布的目录[cite: 1]。
  2. 进入 Actions 页面手动触发一次 Check & Update 流水线[cite: 1]。
  3. 运行成功后，访问 https://你的用户名.github.io/你的仓库名/nodes.txt 检查是否输出节点行[cite: 1]。
  4. 将该 nodes.txt 地址填入 edgetunnel 后台的「自定义优选IP」输入框中保存即可。

常见问题解答 (FAQ)

Q1: 运行后提示“获取原始节点 -1”或“节点数为 0”？

原因： 获取的节点全部是-1,检查更新节点是否能更新，更新不出来就是edge问题，查看邮件看cloudflare的邮件是每日10万请求用完还是被检测滥用了，请求用完第二天 自动回复，检测到滥用，删除项目，重新部署，如果以上都没有还是-1，建议更换优选域名或优选API尝试

Q2: 定时更新频率多久最安全，不容易触发风控？

推荐频率：每 1 到 2 小时运行一次（cron: 0 */2 * * *）。
低于 30 分钟过于频繁，容易触发两层限制：一是 VPN Gate 针对单一 IP 抓取的反爬频率限制；二是 GitHub Actions 免费账户每月的构建时长额度（2000 分钟/月）可能会提前耗尽。

Q3: 为什么必须用 GitHub Actions，不能只用 Cloudflare 部署吗？

核心限制是免费版 Cloudflare Workers 无法支撑重度并发与长耗时任务：

  • CPU 运行时间限制： 免费版 Worker 单次请求的 CPU 运行时间上限仅 10ms-50ms，无法在单次请求中完成几十个上百个节点的大规模并发探测与解包。
  • 出站连接并发与长连接限制： 批量请求外部检测 Worker 及多个数据源时，Worker 会受到子请求总数与总耗时的严格限制。
  • 静态文件托管： GitHub Actions 配合 Pages[cite: 1] 本质上扮演了「免费定时计算服务器」+「静态分发 CDN」的角色，性价比与稳定性远高于单一免费 Worker。
